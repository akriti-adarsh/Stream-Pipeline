# DEVIATIONS

Format: spec said / reality is / what was done. One line each, appended as discovered.

- Spec said Flink consumes the source topics directly; reality is open-source Flink's avro-confluent format has no skip-on-parse-error option, so the generator's deliberate poison messages fail the whole SQL job (json has ignore-parse-errors, avro does not); done: the sessionizer transactionally forwards every clean event to a rides.events.clean mirror (the poison firewall) and Flink reads that, while payments (JSON) sets json.ignore-parse-errors; late/out-of-order data passes through the mirror unchanged.
- Spec said GE freshness on max event_ts within N minutes of now; reality is event time is an accelerated simulation clock that legitimately outruns the wall clock at up to 60x; done: freshness asserted on ingested_at (wall-clock sink landing time) in quality/suites.py.
- Spec said the observability milestone only adds instrumentation and the unit suite passes untouched; reality is the repo-wide lint gate (ruff) was already failing on pre-existing issues in tests/integration (test_dbt_build.py, test_dlq_replay.py, test_late_data.py: subprocess.run without check, unused unpacked vars, unsorted imports, unused noqa, in-function import) left by the dbt/late-data workstream; done: applied the minimal mechanical fixes ruff prescribed, no test logic or assertions changed.
- Spec said verify all Prometheus host targets UP; reality is the iceberg-sink metrics process (port 9104) belongs to the Iceberg milestone and was not running during this session (and the generator's endpoint only lives for the duration of a run, by design); done: both scrape jobs stay configured, the five processes this milestone started showed UP simultaneously, and the down 9104 target correctly drove the TargetDown alert to firing, proving the alert path live.
- Spec said payments.transactions uses registry JSON Schema serialisation; reality is open-source Flink 1.20 has no format for Confluent-framed JSON (only avro-confluent), and the topic feeds the Flink interval join; done: payments travel as plain JSON validated against the JSON Schema subject that remains registered (BACKWARD-pinned) in the registry, so governance is kept and only the 5-byte wire framing is dropped (common/schemas.py: payment_json_bytes / parse_payment).
